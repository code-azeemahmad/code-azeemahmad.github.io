# Product Requirements Document — Static AI Portfolio

## 1. Product summary
Build a static, ChatGPT-inspired AI portfolio that lets visitors explore the owner's biography, experience, projects, products, skills, education, and contact information through a conversational interface.

The site is generated by Astro. A React island powers the interactive chat workspace. Portfolio content is shipped as Markdown/JSON. Visitors can explore preloaded conversations without configuring an AI provider and can optionally bring their own provider API key to continue conversations with a live LLM.

## 2. Goals
- Present the owner's portfolio in a distinctive conversational interface.
- Make verified portfolio information easy to discover.
- Provide curated, preloaded conversations about key portfolio topics.
- Allow visitors to start and manage local conversations.
- Support optional live AI responses through BYOK.
- Work as a static site deployed to GitHub Pages.
- Be responsive, accessible, fast, and search-engine friendly.

## 3. Non-goals
- No owner-operated backend or serverless proxy in the initial strict-static release.
- No database, account registration, login, or server-side session management.
- No server-side RAG or vector database.
- No shared API key paid for by the portfolio owner.
- No guarantee that browser storage is private across people sharing a browser profile.
- No promise of unrestricted general-purpose AI access.

## 4. Target visitors
- Recruiters and hiring managers.
- Potential clients and collaborators.
- Developers interested in the owner's projects and technical skills.
- General visitors exploring the portfolio.

## 5. Core experience
The home page presents a ChatGPT-like workspace:
- A responsive sidebar with a new-chat action, featured conversations, local history, and profile information.
- A welcome screen with a concise introduction and suggested prompts.
- A message area with readable Markdown and code formatting.
- A chat composer with send, stop, and error states.
- Optional theme selection.
- A settings area for BYOK provider configuration and privacy disclosure.

## 6. Featured conversations
Provide immutable JSON templates for:
- About me.
- Projects.
- Experience.
- Products.
- Contact.

When selected, show the predefined messages. If the visitor continues the conversation, create a separate local conversation instance; never mutate the source template.

## 7. Live AI behavior
- Without a provider key, visitors can browse curated content and preloaded answers.
- With BYOK configured, the app retrieves relevant portfolio content, constructs context, and sends the request to the chosen compatible provider.
- Stream responses where the chosen provider/browser integration supports it.
- Clearly indicate that provider requests go directly from the visitor's browser to the provider.
- The assistant must not invent portfolio facts. If retrieved content does not support an answer, it should say so.
- General questions may be answered by the configured model, but the UI should make clear that general model knowledge is not an owner-verified portfolio fact.

## 8. Success criteria
- Production build succeeds as a static site.
- GitHub Pages deployment works at both a user-site root or project-site subpath as configured.
- Main chat workspace works on mobile and desktop.
- Featured conversations work without a provider key.
- Visitor can create, rename, search, and delete local conversations.
- Local conversation history survives reloads on the same browser profile.
- No private/shared API key is present in generated assets.
- Core controls are keyboard accessible.
- All personal portfolio content is owner-verified.

## 9. Content still required from owner
- [OWNER NAME], professional headline, short bio, location (optional), avatar (optional).
- Verified work history, dates, responsibilities, and outcomes.
- Project names, descriptions, technologies, links, screenshots, and measurable results.
- Product details and links.
